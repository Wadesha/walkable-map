步行友好地图 · 原型

一个用来思考“怎么定义 / 组织 / 展示适合步行的区域”的可交互原型。先看懂，再迭代。

⚠️ 本页全部数据均为模拟生成：网格分数、POI、地形坡度都是用噪声函数和人为设定的公式算出来的，仅用于演示交互与说明，不代表任何真实地点的步行友好度。

① 这是什么 / 怎么读

这张图把一片城区切成很多小方格，每个格子算出一个 0–100 的步行友好分数，用红→黄→绿表示：绿=好走，红=难走。

怎么读：

  • 颜色越绿，代表从这片区域步行出行越方便、越舒服、越安全。
  • 点地图上的任意位置，会以该点为中心画一个等时圈——按当前“最大步行时间 / 最大坡度”能走到的范围（蓝色高亮）。
  • 点某个格子，弹窗里给出 5 个维度的拆解分数。
  • 左侧“街区排行”把整片区域分成 9 块，看哪片整体更好走。
0 差50 中100 优
② 步行友好的 5 个维度怎么定义

“好走”不是一句话，而是 5 个可量化维度的加权组合。原型里每个维度都用模拟数据近似：

维度含义原型里的模拟近似
可达性几分钟能走到目的地到各类 POI 的距离衰减求和（越近越高）
连通性路网密不密、街块大不大噪声函数生成“路网密度”，中心略高
舒适性坡度、绿荫、路面噪声生成坡度；公园附近额外加“绿荫”分
安全性车速、过街、照明噪声生成（模拟主干道附近得分低）
吸引力设施种类多不多800m 内覆盖的设施类型数量 / 5

综合分数（权重可在方法学里看到）：
0.30·可达 + 0.18·连通 + 0.17·舒适 + 0.15·安全 + 0.20·吸引。用连续分数而非“好/坏”二分，才有对比和改进空间。

③ 数据从哪来怎么组织

真实项目里，这部分应来自：路网（带属性）、地形 DEM（坡度）、POI（设施）、土地利用（混合度）。本原型用纯前端模拟替代，方便你直接打开就看效果：

  • 网格：以中心点切出 22×22 个方格，每格约 170m（≈3.9km×3.5km 的城区）。
  • POI：手工摆了 8 个模拟点（公园×2、地铁×2、商铺×2、学校×1、医院×1）。
  • 分数：每个格子按上面 5 个维度分别计算，再加权合成，见方法学。
  • 等时圈：从点击点出发，步行速度 80m/分 × 时间 得到半径，且坡度不超过阈值——满足的格子高亮。

注意：距离用的是直线距离（欧几里得），不是真实路网步行距离；等时圈因此是“近似圆”，真实情况会被道路走向、围墙、河流切碎。这是原型的已知简化。

④ 方法学 / 评分公式透明

为了让“模拟”可被检验，公式完全公开。设格子中心为 c，POI 集合为 P：

可达性 access = min(100, Σ w_t · exp(-d/450)) · 55
其中 d 是 c 到第 t 类 POI 的距离(米)，w = 公园1.0 / 地铁1.2 / 商铺0.9 / 学校0.7 / 医院0.8，仅计入 1400m 内。

吸引力 attr = min(100, 800m内覆盖的设施类型数 / 5 × 100)。

连通性 conn = 20 + 60·noise(c) + 10·(1 − min(1, 到中心距离/1500))。

舒适性 comfort = clamp(90 − 坡度°×4 − (1−noise₂)×20 + 公园附近绿荫, 0, 100)。

安全性 safety = clamp(95 − 40·noise₃, 0, 100)（模拟主干道附近偏低）。

noise 是 (sin+cos 组合 + 4)/8 的平滑伪随机，保证相邻格相近、整片有起伏。

综合 score = 0.30·access + 0.18·conn + 0.17·comfort + 0.15·safety + 0.20·attr。

⑤ 能做什么 / 已知局限诚实

这个原型能帮你：

  • 把“步行友好”从一句口号，变成可看、可点、可对比的地图。
  • 验证“定义→组织→展示”这条链路在网页上是否走得通。
  • 作为和规划者 / 居民讨论的可视化沟通工具。

局限（下一步要补的）：

  • 距离是直线，不是真实路网步行距离。
  • 坡度/安全是噪声模拟，不是真实 DEM 与事故数据。
  • 没有后端，刷新即重算；真实项目应接 PostGIS + OSRM/Turf 等服务。
  • 权重是拍定的，真实项目应由居民调研或文献确定。
